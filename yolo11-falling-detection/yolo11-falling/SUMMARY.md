# 基于改进 YOLO11 的智能摔倒检测系统 — 项目总结

---

## 一、理论与方案设计

### 1.1 核心算法理论

本系统以 YOLO11（You Only Look Once v11）为核心检测引擎。YOLO 系列算法的核心思想是将目标检测转化为回归问题，通过单个卷积神经网络一次性预测图像中所有目标的边界框和类别概率，避免了传统两阶段检测器（如 Faster R-CNN）中候选区域生成和分类的分离过程。

**YOLO11 架构创新：**

- **C3k2 模块**：CSP（Cross Stage Partial）瓶颈的紧凑版本，通过拆分特征图通道减少计算冗余，在保持特征表达能力的条件下降低 15%-20% 的计算量
- **改进的特征金字塔网络（FPN + PAN）**：自顶向下传递语义信息，自底向上传递定位信息，实现多尺度特征深度融合
- **解耦头（Decoupled Head）**：分类和回归分支独立计算，减少任务冲突，提升收敛速度

**注意力机制增强（CBAM）：**

系统引入了 CBAM（Convolutional Block Attention Module）注意力机制，在不显著增加计算开销的前提下提升检测精度。CBAM 包含两个串行子模块：

1. **通道注意力（Channel Attention）**：通过全局平均池化和最大池化聚合空间信息，经 MLP 学习各通道的重要程度
2. **空间注意力（Spatial Attention）**：沿通道维度进行池化操作，通过卷积层生成空间注意力图，聚焦于目标关键区域

数学表达：
```
F' = Mc(F) ⊗ F          (通道注意力加权)
F'' = Ms(F') ⊗ F'       (空间注意力加权)
```

**多目标追踪算法：**

- **ByteTrack**：创新性地利用低置信度检测框进行二次关联，有效减少因遮挡导致的 ID Switch
- **BoT-SORT**：在 ByteTrack 基础上引入相机运动补偿（CMC）和改进的 ReID 特征提取，追踪稳定性进一步提升

```
┌──────────────────────────────────────────────────────────────────┐
│                        离线闭环检测流程                            │
│                                                                  │
│  ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐   │
│  │ 1.数据   │───▶│ 2.算法   │───▶│ 3.反馈   │───▶│ 4.物理   │   │
│  │   采集   │    │   推理   │    │   结果   │    │   执行   │   │
│  └──────────┘    └──────────┘    └──────────┘    └──────────┘   │
│       │               │               │               │          │
│       ▼               ▼               ▼               ▼          │
│  ·摄像头抓帧     ·YOLO11检测    ·标注框渲染    ·声光报警器    │
│  ·图片上传      ·站立/摔倒分类  ·计数统计      ·短信/邮件通知  │
│  ·视频抽帧      ·ByteTrack追踪 ·结果存储      ·微信消息推送   │
│  ·预处理增强    ·置信度过滤    ·历史回溯      ·联动摄像头录像  │
│                                                                  │
│  ◀──────────────── 数据回流（持续优化）─────────────────────      │

### 2.2 各环节详解

**环节一：数据采集**

| 采集方式 | 适用场景 | 技术实现 |
|----------|----------|----------|
| 监控摄像头 RTSP 流 | 养老院、医院病房 | OpenCV VideoCapture + 定时抽帧 |
| 移动端拍照上传 | 居家个人使用 | 微信小程序 `wx.chooseImage` |
| 批量图片导入 | 事后分析、模型训练 | 文件夹批量推理 `detect_folder.py` |
| 视频文件回放 | 历史录像分析 | 逐帧检测 + 追踪轨迹绘制 |

**环节二：算法推理**

1. 图像预处理：缩放至 640×640，保持宽高比填充
2. 模型推理：YOLO11s 前向传播，输出边界框 + 类别 + 置信度
3. 后处理：NMS 去重 → 置信度过滤（默认 0.25）→ IoU 过滤（默认 0.45）
4. 追踪（可选）：ByteTrack 跨帧关联，绘制运动轨迹

**环节三：反馈结果**

| 反馈形式 | 响应时间 | 实现方式 |
|----------|----------|----------|
| 图像标注框 | < 50ms | OpenCV 绘制 + 类别文字 + 置信度 |
| 统计计数 | 实时 | 各类别目标数量汇总 |
| 历史记录 | 持久化 | wx.Storage / 本地 JSON |
| CSV 导出 | 批量 | NumPy savetxt 结构化输出 |

**环节四：物理执行**

| 执行动作 | 触发条件 | 实现方式 |
|----------|----------|----------|
| 声光报警 | 检测到摔倒 | GPIO 继电器 / 智能音箱 TTS |
| 短信通知 | 检测到摔倒 | SMSBao API / 阿里云短信 |
| 邮件告警 | 检测到摔倒 | SMTP 邮件（含检测截图） |
| 微信推送 | 检测到摔倒 | 小程序订阅消息 / 企业微信 |
| 录像标记 | 事件前后 30s | FFmpeg 视频片段截取 |
| 灯光联动 | 夜间摔倒 | MQTT → 智能家居平台 |

### 2.3 闭环自优化

系统支持将检测结果回流至训练集：

```
误报样本 → 人工标注修正 → 加入训练集 → 模型重训练 → 精度提升
漏检样本 → 补充标注 → 数据增强 → 模型微调 → 召回率提升
```

## 三、技术逻辑

### 3.1 推理管道（Inference Pipeline）

```
输入图像 (任意分辨率)
    │
    ▼
[1] 预处理 (Preprocessing)
    ├── 色彩空间: BGR → RGB
    ├── 尺寸缩放: Letterbox → 640×640
    ├── 归一化: pixel / 255.0
    └── 转 Tensor: HWC → BCHW
    │
    ▼
[2] 骨干网络 (Backbone: YOLO11 + C3k2)
    ├── Conv(3→64, k=3, s=2)
    ├── C3k2(64→128) × 2  ──── P3
    ├── C3k2(128→256) × 2  ──── P4
    ├── C3k2(256→512) × 2  ──── P5
    └── SPPF(512→512)
    │
    ▼
[3] 颈部网络 (Neck: FPN + PAN)
    ├── Top-Down:  P5 → P4 → P3  (语义增强)
    └── Bottom-Up: P3 → P4 → P5  (定位增强)
    │
    ▼
[4] 检测头 (Head: Decoupled)
    ├── Cls Branch: 分类 (Sigmoid → 2类)
    └── Box Branch: 回归 (Distributed Focal Loss → bbox)
    │
    ▼
[5] 后处理 (Postprocessing)
    ├── NMS (IoU=0.45)
    ├── Conf Filter (min=0.25)
    └── Rescale bbox → 原始图像坐标
    │
    ▼
输出: [(class, confidence, x1, y1, x2, y2), ...]
```

### 3.2 追踪管道（Tracking Pipeline）

```
第 t 帧检测结果
    │
    ▼
[1] 高分框匹配 (High-score Association)
    ├── 检测框 (conf > 0.6) 与现有轨迹的 Kalman 预测匹配
    └── 匹配成功 → 更新轨迹状态
    │
    ▼
[2] 低分框匹配 (Low-score Association)  ← ByteTrack 创新点
    ├── 检测框 (0.1 < conf ≤ 0.6) 与未匹配轨迹匹配
    └── 匹配成功 → 恢复被遮挡目标
    │
    ▼
[3] 新轨迹初始化
    ├── 仍未匹配的高分框 → 创建新轨迹
    └── 连续 3 帧确认 → 激活轨迹
    │
    ▼
[4] 轨迹管理
    ├── 连续 30 帧未更新 → 标记为丢失
    └── 超过阈值 → 删除轨迹
    │
    ▼
输出: [(track_id, bbox, class), ...]
```

### 3.3 数据流架构

```
┌─────────┐    REST API     ┌──────────────┐    Python SDK    ┌──────────┐

## 四、场景与人物描述

### 4.1 场景一：独居老人家中

**人物：** 张大爷，78 岁，独居，患有轻度骨质疏松

**场景描述：**

凌晨 3:15，张大爷起夜去卫生间，在走廊拐角处因地面湿滑不慎摔倒，无法自行站起。客厅安装的摄像头捕捉到这一画面：

- **T+0s**：摄像头帧送入 YOLO11 模型，检测到人体姿态从"站立"突变为"摔倒"
- **T+0.2s**：ByteTrack 追踪确认同一目标持续处于摔倒状态（连续 10 帧判定，防止误报）
- **T+2s**：系统触发三级告警：短信发送至儿子手机、APP 推送至社区养老服务中心、室内智能音箱播放求助语音
- **T+5s**：儿子通过微信小程序查看实时画面，确认情况后拨打 120
- **T+15min**：救护车到达，张大爷得到及时救治

**价值体现：** 从摔倒发生到家属获知仅 2 秒，大幅缩短了"黄金救援时间窗口"。

### 4.2 场景二：养老院公共区域

**人物：** 护理员小王，负责 20 位老人的日间照护

**场景描述：**

午休后自由活动时间，多位老人在活动室、走廊、花园等区域活动。小王无法同时照看所有区域：

- **10:23**：活动室东南角，李奶奶在起身时站立不稳摔倒
- **T+0s**：SAHI 切片检测模式捕获大场景中的小目标摔倒事件
- **T+1s**：护士站大屏弹出告警，标注李奶奶的位置和实时画面
- **T+3s**：BoT-SORT 追踪确认摔倒持续，系统通过 MQTT 联动走廊警示灯闪烁
- **T+30s**：小王赶到现场搀扶李奶奶，确认仅轻微擦伤

**价值体现：** 一名护理员借助系统可有效监护 20+ 位老人，人力效率提升 3-5 倍。

### 4.3 场景三：康复医院步态分析

**人物：** 康复医师陈医生，负责中风患者术后步态评估

**场景描述：**

陈医生需要客观评估患者在康复训练中的步态稳定性和摔倒风险：

- 患者在平行杠内进行 3 分钟步行训练
- 系统实时追踪患者轨迹，记录重心位移曲线
- YOLO11 输出每一帧的人体姿态（站立/弯腰/摔倒）
- 训练结束后生成步态报告：总步数、不稳定性事件次数、摔倒风险评分
- 陈医生根据数据调整康复方案

**价值体现：** 量化评估替代主观观察，康复效果可追踪、可对比。

## 五、创新性

### 5.1 算法创新

**1. 多架构融合对比框架**

不同于单一模型方案，系统内置 YOLOv5/v8/v11 + CBAM/GhostConv 共 7 种配置，支持一键切换对比。用户可根据实际场景（精度优先/速度优先/边缘部署）灵活选型。

**2. 双层注意力机制**

在 YOLO11 骨干网络中嵌入 CBAM 注意力模块，通道注意力和空间注意力协同工作，在不显著增加参数量的前提下提升对"人体姿态突变"这一关键特征的敏感度。

**3. 切片-全局联合推理**

创新性地将 SAHI 切片检测与 ByteTrack 追踪结合：大场景使用 SAHI 切片提升小目标检出率，追踪算法在全局坐标系中关联目标，解决了"切片边界目标丢失"问题。

### 5.2 系统创新

**4. 三端统一架构**

桌面客户端（PySide6）、Web 演示（Gradio）、微信小程序共享同一套 FastAPI 后端，前端仅负责展示和交互，模型更新无需客户端升级。

**5. 离线闭环自优化**

检测结果（误报/漏检）可经人工修正后回流至训练集，形成"部署 → 反馈 → 优化 → 再部署"的持续改进闭环。

**6. 模型热切换**

运行时通过 API 动态切换模型权重，无需重启服务，支持 A/B 测试和灰度发布。

### 5.3 应用创新

**7. 非接触式零负担监测**

与可穿戴设备（手环、挂坠）方案相比，基于视觉的方案无需用户佩戴任何设备、无需充电、无遗忘风险，特别适合认知能力下降的老年用户。

**8. 分级告警策略**

单帧检测 + 连续帧确认 + 人工复核的三级判定机制，有效平衡"及时性"和"误报率"。

## 七、技术难点与解决方案

### 7.1 姿态相似性区分

**难点：** 蹲下、弯腰、躺下等动作与摔倒的姿态高度相似，单帧图像易误判。

**方案：**
- ByteTrack 追踪连续帧，计算目标运动速度和加速度
- 摔倒事件满足"高度骤降 + 速度突变 + 姿态持续"三个条件才触发告警
- 在训练集中增加易混淆动作的负样本

### 7.2 光照与环境适应性

**难点：** 夜间、逆光、阴影等复杂光照条件严重影响检测精度。

**方案：**
- 训练阶段采用 HSV 色彩抖动、随机亮度/对比度增强
- 推理阶段使用 CLAHE（自适应直方图均衡化）预处理低照度帧
- 红外摄像头 + 可见光模型联合推理（夜间切换红外模式）

### 7.3 隐私保护

**难点：** 摄像头监控涉及个人隐私，尤其在卧室、卫生间等私密空间。

**方案：**
- 边缘端推理，原始视频不出本地，仅上传告警事件截图
- 支持人体骨骼关键点模式（仅传输 17 个关节点坐标，不传输原始图像）
- 数据脱敏：人脸模糊处理后再存储
